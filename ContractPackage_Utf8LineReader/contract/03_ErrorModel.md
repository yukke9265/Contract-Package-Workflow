# エラーモデル

## 1. 失敗通知方針

- 失敗通知方法: `LineReaderStatus` による戻り値通知
- `noexcept` 方針: 公開 API は全面的に `noexcept`
- 契約違反時の扱い: 例外は投げず、`Open` 前の `ReadLine` は `not_open` を返す
- 未定義動作: 許可しない

## 2. 例外 / エラー返却

| 名前 | 発生条件 | 呼び出し側の期待動作 |
| --- | --- | --- |
| `ok` | 操作成功 | 通常処理を継続する |
| `end_of_file` | 最後の行まで読み切った | 正常終了としてループを抜ける |
| `not_open` | `Open` 前に `ReadLine` を呼んだ、または open に失敗した状態で読み取った | 呼び出し順を修正し、必要なら `Open` を再実行する |
| `invalid_utf8` | 読み込んだ行が UTF-8 として不正 | 入力不正として中断し、`Close` する |
| `io_error` | ファイル読取中に OS / デバイス由来の I/O エラーが発生 | 中断し、`Close` した上で上位へ通知する |

## 3. 例外安全保証

| 操作 | 保証レベル | 説明 |
| --- | --- | --- |
| `Utf8LineReader()` | no-throw | 失敗しても例外を送出しない |
| `Open` | basic | 失敗時は `IsOpen() == false` を保証する |
| `ReadLine` | basic | 失敗時もオブジェクト破壊なしで `Close` を呼べる |
| `Close` | no-throw | 何度呼んでも例外を送出しない |

## 4. 部分更新と回復

- 部分成功の扱い: 不可。1回の `ReadLine` は1行成功か失敗のいずれか
- 失敗時の状態: `invalid_utf8` または `io_error` 発生後は継続読取状態を保証しない
- 再試行可否: `not_open` は `Open` 後に再試行可。`end_of_file` は同一ファイルに対する再試行不可。`io_error` は `Close` と `Open` のやり直し後のみ条件付きで再試行可
- 補償動作: 必要なら失敗前までに処理済みの行だけを上位が採用する
